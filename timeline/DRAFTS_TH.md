# ฟอร์มเรื่องราวและ Draft ในเบราว์เซอร์

## การปิดฟอร์ม

- ฟอร์มเพิ่ม/เสนอแก้ไขเรื่องราวไม่ปิดจาก Cancel ในตัวเลือกไฟล์, การเลือกไฟล์ว่าง, Escape หรือคลิกนอกกรอบ
- ปิดด้วยปุ่ม × หรือเมื่อส่งเรื่องราวสำเร็จ การปิดเองและส่งสำเร็จจะล้าง draft ของฟอร์มนั้น
- รีเฟรช ปิดแท็บ/เบราว์เซอร์ เปลี่ยนหน้า หรือหลุดจาก session จะเก็บ draft ไว้ และกู้กลับเมื่อบัญชีเดิมเปิดหัวข้อเดิมอีกครั้ง
- Dialog อื่น เช่น Login ยังคงปิดด้วย Escape ได้

สาเหตุเดิมคือ [`cancel` ของ input เลือกไฟล์สามารถ bubble ได้](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/cancel_event) `Modal.tsx` จึงตรวจว่า event มาจากตัว dialog เองก่อนพิจารณาปิด และ ContentForm กำหนดไม่ให้ Escape ปิดฟอร์ม

## ข้อมูลที่กู้คืน

- ชื่อ เนื้อเรื่อง เวลา (รวมค่าที่ยังกรอกไม่ครบ) แหล่งอ้างอิง และชื่อเฉพาะที่ยังไม่บันทึก
- รายการสื่อ ลำดับ คำบรรยาย แหล่งที่มา และการเลือกภาพปก
- ไฟล์ภาพ/PDF ที่เลือกไว้ รวมไฟล์ระหว่างอัปโหลดและไฟล์ที่อัปโหลดเสร็จแล้ว
- บริบทฟอร์มสร้างใหม่/แก้ไขเรื่องราว/แก้ไขคำขอ พร้อม revision หรือรอบโหวตเดิม เพื่อให้ Server ยังปฏิเสธการเขียนทับเวอร์ชันที่เปลี่ยนไปแล้ว
- Operation ID ของการส่ง เพื่อให้ลองใหม่หลัง response หายได้โดยไม่สร้างเรื่องราวซ้ำ

ข้อความและข้อมูลฟอร์มเขียนลง `localStorage` ทันทีที่เปลี่ยนค่า ไฟล์เก็บใน IndexedDB แยกตาม Firebase project, บัญชี, หัวข้อ และฟอร์ม จึงไม่ดึง draft ข้ามบัญชีหรือหัวข้อ ไม่เก็บรหัสผ่านใน draft

Draft ใช้กับเบราว์เซอร์และโปรไฟล์เดิม ไม่ซิงก์ข้ามเครื่อง หากล้างข้อมูลเว็บไซต์ draft จะหาย หากเบราว์เซอร์ปิดกั้นหรือพื้นที่จัดเก็บเต็ม ฟอร์มจะแจ้งว่าบันทึก draft ไม่ได้และยังพิมพ์ต่อได้

ไฟล์ต้นฉบับถูกเก็บไว้จนกดปิดเองหรือส่งสำเร็จ หาก Server cleanup สื่อ orphan ของ draft เก่าไปแล้ว ระบบใช้สำเนาในเบราว์เซอร์อัปโหลดใหม่และแทนที่ ID เดิม พร้อมรักษาคำบรรยาย ลำดับ และภาพปก

## ข้อกำหนดสื่อและฟอร์ม

- อัปโหลดเฉพาะ JPEG, PNG, WebP, GIF และ PDF ไม่เกิน 5 MB ต่อไฟล์ รวมไม่เกิน 20 รายการ
- ไม่รับ DOCX ทั้ง Client, `prepareUpload`, `finalizeUpload` และ Storage Rules เอกสาร DOCX เก่าที่เผยแพร่แล้วคงอ่านได้
- ยกเลิกตัวเลือกชนิดลิงก์ ช่องลิงก์ HTTPS และปุ่มเพิ่มลิงก์ของสื่อ ส่วน URL ของแหล่งอ้างอิงวิดีโอยังเป็นไปตามฟอร์มแหล่งอ้างอิง
- ยกเลิกช่องเวอร์ชันเรื่องราว/เกมและภาษาเรื่องราว ข้อมูลเดิมยังเก็บเพื่อรองรับประวัติ
- ลบข้อความ “เรื่องราวและแหล่งอ้างอิงที่ชุมชนส่งมา” และจัดปุ่มกลับไปแก้ไข/ส่งเรื่องราวในแถวเดียวกัน

## การอัปโหลดต่อ

Client ส่ง `uploadId` ที่คงเดิมสำหรับไฟล์ draft แต่ละรุ่น Server สร้าง media ID จาก account/draft/upload identity และคืน descriptor เดิมเมื่อส่งซ้ำ ไม่หักโควตาอัปโหลดซ้ำ

`prepareUpload` ตอบสถานะ staging/ready/expired และบอกว่ามี bytes ใน staging แล้วหรือไม่ ทำให้กู้ขั้นตอนก่อนอัปโหลด หลังอัปโหลด หรือหลัง finalize สำเร็จแต่ response หายได้ ไฟล์ของอีกบัญชีไม่ใช้ identity เดียวกัน

Web Locks ทำให้หลายแท็บไม่ประมวลผลไฟล์ draft เดียวกันพร้อมกัน ในเบราว์เซอร์ที่ไม่มี Web Locks ยังมี descriptor/operation idempotency ฝั่ง Server ป้องกันข้อมูลซ้ำ

## ไฟล์หลัก

- `src/features/timeline/Modal.tsx`, `ContentForm.tsx`, `TimelineApp.tsx`: วงจรฟอร์มและการกู้คืน
- `drafts.ts`, `useStoryDraft.ts`: ข้อมูล draft, การตรวจรูปแบบ และ localStorage
- `draftUploads.ts`, `MediaFields.tsx`: สำรองไฟล์ใน IndexedDB และอัปโหลดต่อ
- `functions/src/media.ts`, `storage.rules`: ตรวจชนิดไฟล์และการอัปโหลดที่ลองซ้ำได้
- `StoryBody.tsx`, `style.css`: ข้อความและปุ่มในหน้าตรวจสอบก่อนส่ง

## ทดสอบและเปิดใช้

เปิด Emulator และ Vite ก่อน จากนั้นรัน:

```powershell
npm run check
npm run test:drafts:integration
npm run test:drafts:browser
npm run test:browser
```

หลักฐานอยู่ที่ `evidence/timeline/drafts-integration.json`, `drafts-browser.json`, `browser.json`, `unit.log`, `build.log` และ `lint.log` ชุดทดสอบสร้างเฉพาะข้อมูลสังเคราะห์ใน Emulator และล้างหัวข้อของรอบตัวเองเมื่อจบ
