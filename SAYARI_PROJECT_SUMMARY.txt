4. Zenless Zone Zero — สูตรและสถานะ
====================================
ไฟล์หลัก:
  index.tsx: ชุดตัวอย่างสถิติ agent และหน้าตารางการ์ด
  card.tsx: inputs DEF/RES/ดาเมจจริง และสูตรคำนวณย้อนกลับ
  type.ts: TAgentStat
  data.ts: agent metadata 26 รายการ และ Thanatos lv70 def1025

TAgentStat มี name, element, lv, atk, critRate, critDmg, penPercent, penBonus, bonus,
multiplier และ ingameDmg?
element literal ใช้ "ligntning" ซึ่งสะกดผิด และ metadata ใช้ "Electric" ซึ่งเป็นอีก convention

ตัวอย่างที่แสดงจริง 4 ใบ:
  Piper: lv60, ATK2777, CR12.2, CD78.8, PEN%=0, flatPEN36, bonus30, multiplier140, ingame4861
  Neko:  lv60, ATK2948, CR72.2, CD126.8, PEN%=0, flatPEN45, bonus60, multiplier106.2, ingame4872
  Ellen: lv60, ATK3358, CR72.2, CD112.4, PEN%=0, flatPEN36, bonus0, multiplier98.3, ingame3810
  Ellen: lv60, ATK3259, CR65, CD64.4, PEN%=0, flatPEN36, bonus0, multiplier98.3, ingame3082
มีตัวอย่างอื่นใน comment แต่ไม่ได้ render
agent metadata และ Thanatos ใน data.ts ไม่ได้ import มาใช้ในหน้าคำนวณปัจจุบัน

สูตรใน Card:
  B = atk × (multiplier/100) × (1 + bonus/100)
  L = 100 + 10 × agentLevel
  effectiveDef(D) = max(D × (1 − penPercent/100) − penBonus, 0)
  defMultiplier(D) = L / (effectiveDef(D)+L)
  resistMultiplier = 1 − monsterResist/100
  finalCal = B × defMultiplier(monsterDef) × resistMultiplier
  inferredDef = [L / (observedDamage/(B×resistMultiplier)) − L + penBonus]
                / (1 − penPercent/100)
  ในการย้อนกลับ observedDamage ใช้ Number(ingameDmg)||1 ซึ่งเปลี่ยน 0/NaN เป็น 1
  CritDmgCal แสดง B × (1+critDmg/100)

ค่าเริ่มต้น:
  monsterDef="", monsterResist="0" → numeric DEF=0 และ RES=0
  ingameDmg มาจาก sample data; แต่ละ Card มี state ของตนเอง
  finalCal เริ่มประมาณ 5054.14, 5009.2416, 3300.914, 3203.597 ตามลำดับ

ข้อจำกัด/จุดควรแก้:
  • ข้อความสูตรบนหน้าอ้าง CRIT/DMG Taken/Stunned multipliers แต่ finalCal ยังไม่รวมทุกส่วน
  • critRate ไม่ได้มีผลกับ expected damage และไม่ได้ใช้ในสูตรที่ render จริง
  • finalCal ถูก console.log แต่ไม่มีข้อความผลลัพธ์สุดท้ายแบบตรงไปตรงมาใน UI
  • แถว diff ใช้ B−observedDamage ไม่ใช่ finalCal−observedDamage
  • ช่องแก้ ingameDmg กลับใส่ value เป็นข้อความ "base - critical" แล้ว parse กลับเป็นตัวเลข
    เช่นข้อความที่มีค่าทั้งสองอาจกลายเป็น NaN; ควรแยก numeric input กับข้อความเปรียบเทียบ
  • ตัวกรอง replace(/[^\d.]/, "") และ replace(/[^\d.-]/, "") ไม่ใช้ g
    จึงลบเพียงอักขระผิดตัวแรก และไม่รับประกันว่ามีจุด/เครื่องหมายลบถูกตำแหน่ง
  • RES>=100 ทำให้ multiplier เป็นศูนย์หรือติดลบ; สูตรย้อนกลับไม่มี guard
  • penPercent=100 ทำให้สูตรย้อนกลับหารศูนย์หากเพิ่มชุดข้อมูลเช่นนั้น
  • ไม่ clamp inferredDef เป็นค่าที่มีความหมาย; sample บางค่าใหญ่กว่า B ทำให้ได้ DEF อนุมานติดลบ
  • UI แสดง multiplier เป็น Math.round(multiplier)/100 แต่สูตรใช้ทศนิยมเดิม จึงแสดงค่าปัดคนละความละเอียด
  • Layout xs=3 ตายตัว 4 คอลัมน์ ไม่มี breakpoint สำหรับหน้าจอเล็ก
ยังไม่ได้ตรวจความถูกต้องของสูตรกับข้อมูลเกมปัจจุบันหรือ training dummy จริง

8. หลักฐานและผลตรวจล่าสุด
=========================

  • สำรวจ inventory ใหม่ และบันทึก SHA-256 ของไฟล์ที่ยังอยู่ทั้งหมด

9. ประเด็นแนะนำให้พัฒนาต่อ
=========================
แยก observed damage numeric input ของ ZZZ ออกจากข้อความเปรียบเทียบ critical
เพิ่ม guard ของ NaN/Infinity, RES100 และ denominator เป็น0

แยก pure calculation functions แล้วเพิ่ม tests ของสมการและ edge cases ที่มีผลจริง
ปรับ mobile layout จาก xs=3 ตายตัว และเพิ่มการใช้งานผ่าน keyboard
เพิ่ม Firebase SPA rewrite แล้วตรวจ deep link จริง
ปรับ title/favicon/lang และเขียน README แทน Vite template; README เดิมมี NUL bytes ตอนท้าย
ยังมี working-tree changes/untracked files เดิมจำนวนมาก ให้รักษางานที่ไม่เกี่ยวข้องและไม่ reset/clean โดยพลการ
